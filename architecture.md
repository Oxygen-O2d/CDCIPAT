# CDCIPAT MiniLang Compiler Architecture

This document outlines the architecture for the CDCIPAT MiniLang Compiler project. The system is divided into a **React/Vite Frontend** for visualization and a **FastAPI (Python) Backend** for the core compilation logic.

## 🖥️ Frontend Architecture

The frontend is a **React** application bundled with **Vite**. It is designed to be an educational playground, exposing the internal workings of the compiler pipeline.

### Key Components:
- **`Editor.jsx`**: Provides the code editing interface where users write MiniLang source code.
- **Visualizer Components**: A suite of components dedicated to displaying the outputs of the backend pipeline:
  - **`TokensTable.jsx`**: Displays the output of the Lexer (Token type, value, line, column).
  - **`TreeVisualizer.jsx` / `ParseTrace.jsx`**: Visualizes the Abstract Syntax Tree (AST) generated by the Parser.
  - **`SymbolTable.jsx`**: Shows declared variables, their types, and scopes.
  - **`SemanticChecks.jsx`**: Lists semantic errors and warnings (e.g., type mismatches, undeclared variables).
  - **`IntermediateCode.jsx`**: Displays the generated Three-Address Code (TAC).
  - **`OutputView.jsx`**: Shows the final console output from the Executor.
- **`PipelineStatus.jsx`**: Tracks and displays the current stage of the compilation process (e.g., Lexical Analysis, Syntax Analysis, etc.).

## ⚙️ Backend Architecture (Compiler Pipeline)

The backend is built with **FastAPI** in Python. It avoids external parser generators (like ANTLR or YACC) to demonstrate a from-scratch implementation of compiler phases.

### 1. API Layer (`main.py`)
- Receives the raw source code via a `POST /api/compile` request.
- Orchestrates the 5-stage pipeline, catching exceptions at each step (`LexerError`, `ParseError`, etc.).
- Aggregates the intermediate data (Tokens, AST dict, Symbol Table, TAC, Output) and returns it as a unified JSON response to the frontend.

### 2. Lexical Analysis (`lexer.py`)
- **Input:** Raw source code string.
- **Mechanism:** Uses Python's `re` (Regular Expressions) module.
- **Action:** Scans the text, stripping whitespace and comments, and converts character sequences into discrete `Token` objects (e.g., `INT_CONST`, `IDENT`, `IF`, `WHILE`).

### 3. Syntax Analysis (`parser.py` & `ast_nodes.py`)
- **Input:** List of `Token` objects.
- **Mechanism:** Hand-written **LL(1) Recursive-Descent Parser**.
- **Action:** Consumes tokens strictly according to the MiniLang EBNF grammar. Constructs an Abstract Syntax Tree (AST) using hierarchical nodes (e.g., `BinOpNode`, `IfNode`, `AssignNode`). Enforces operator precedence implicitly through the structure of recursive function calls.

### 4. Semantic Analysis (`semantic.py`)
- **Input:** Abstract Syntax Tree (AST).
- **Mechanism:** AST Traversal (Visitor Pattern).
- **Action:** 
  - Builds the **Symbol Table** to track variable declarations.
  - Performs **Type Checking** (ensuring operations between `num` and `dec` are valid).
  - Emits semantic errors (fatal) and warnings (non-fatal, e.g., implicit precision loss).

### 5. Intermediate Code Generation (`codegen.py`)
- **Input:** Abstract Syntax Tree (AST).
- **Mechanism:** AST Traversal.
- **Action:** Lowers the hierarchical AST into flat, linear **Three-Address Code (TAC)**. It uses temporary variables (`t1`, `t2`) for arithmetic and `GOTO` labels (`L1`, `IF_FALSE`) for control flow branching.

### 6. Execution (`executor.py`)
- **Input:** Abstract Syntax Tree (AST).
- **Mechanism:** AST-Walking Interpreter.
- **Action:** Recursively evaluates the AST nodes in a simulated environment (Python dictionary) to execute the logic and capture `output()` statements. 
  - *Note: It directly evaluates the AST rather than interpreting the generated Three-Address Code, acting as a direct interpreter.*

## 🔄 Data Flow Summary

1. User types code in the React `Editor`.
2. React sends a JSON payload `{ "code": "..." }` to FastAPI.
3. The string passes through the pipeline: `String -> Tokens -> AST -> TAC & Output`.
4. If a pipeline stage fails (e.g., Syntax Error), execution halts, and the error is returned alongside the data from the successful stages.
5. FastAPI returns a large JSON object containing the tokens, AST dictionary, symbol table, TAC array, and final output array.
6. React parses this JSON and distributes the data to the respective visualization components (Tabs/Tables) for the user to inspect.
